# 搭建规范

## 1. 盘点

- 列出根目录下的一、二级结构，统计各类文件的数量（文档、表格、图片、音视频、压缩包等）。
- 文件超过几百个时，每个子文件夹抽看几份，并说明抽样范围。
- 记下已有的说明文件、编号习惯和命名规则。能沿用的就沿用。
- 压缩包和下载来的文件只看文件名，不解压、不运行。

## 2. 问清用途

最多问 3 个问题，用户已经说过的跳过：

1. 主要给谁用、查什么？（例如：自己复习课程、团队查业务资料）
2. 资料会持续增加吗？主要从哪里来？
3. 有没有必须保持原样的文件或目录？

## 3. 方案内容

方案交给用户确认，包含：

- **分区**：每个分区的名称、放什么资料、对应哪些现有文件夹。分区按“用户怎么查”来划分，不按文件格式划分。
- **来源类型**：例如原始文件、转写稿、精编稿、个人笔记、提示词、实践产出、AI 整理。导航里要标出每个分区的来源类型。
- **版本规则**：同一资料有多个版本时以哪份为准，例如“精编稿优先于转写稿”“标明最终版的优先”。规则由用户确定，AI 只给建议。
- **搬动清单**（如果需要）：用表格列出“原路径 → 新路径 → 原因”。不搬动也能建导航时，优先不搬。

## 4. 根导航模板

文件名沿用用户习惯。没有习惯时用 `README.md`；需要强调版本规则时可用 `SOURCE_OF_TRUTH.md`。

```markdown
# <知识库名称>

<一句话：这个知识库收什么、给谁用。>

## 从这里找

| 想找 | 入口 | 说明 |
|---|---|---|
| <主题> | [<分区>/README.md](<分区>/README.md) | <来源类型；覆盖范围> |

## 版本规则

- <多个来源冲突时以哪份为准>
- 规则不明确时报告冲突，不自行认定。

## 收录新资料

- 新资料放入对应分区，并在该分区 README 中加一行。
- 不属于任何分区时，先放 `待整理/`，再决定归属。

## 不作为知识来源

- <例如 备份、回收站、安装包>
```

## 5. 分区 README 模板

```markdown
# <分区名>

<这个分区收什么。来源类型：…>

| 文件 | 内容 | 类型 | 状态 |
|---|---|---|---|
| [<文件名>](<文件名>) | <一句话> | <原文/转写/笔记…> | <完整/缺口/待核验> |

缺口：<已知缺失的资料，没有就写“暂无”>
```

## 6. 验收

- 根导航和分区 README 里的链接全部能打开。
- 列出新建的文件，以及仍未收录的文件。
- 执行过搬动时，附上实际执行的“原路径 → 新路径”记录。
- 不把“建好了目录”说成“资料已经完整”。
