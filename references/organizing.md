# 整理规范

## 1. 体检项目

| 检查项 | 怎么查 | 结论写法 |
|---|---|---|
| 失效链接 | 逐个检查导航和 README 里的相对链接 | 列出所在文件和失效目标 |
| 未收录文件 | 对比目录里的实际文件和导航里的条目 | 列出路径，建议归入哪个分区 |
| 疑似重复 | 文件名相近、大小相同或内容开头相同 | 标为“疑似”，需要时再比对内容 |
| 版本冲突 | 同一主题有多份资料，说法或数据不同 | 列出各版本路径和差异，按版本规则给建议 |
| 命名与位置 | 命名风格不一致、文件放错分区、空目录 | 给出建议名称或位置 |
| 导航过期 | 导航里的说明和实际内容不符 | 指出具体条目 |

大型知识库先查用户关心的区域，并说明没有检查的范围。

## 2. 报告格式

```markdown
## 知识库体检报告（<日期>）

检查范围：<路径；未检查的部分>

### 确定的问题
| 类型 | 路径 | 建议 |
|---|---|---|

### 疑似问题（需要你确认）
| 类型 | 路径 | 依据 |
|---|---|---|

### 需要你授权的操作
| 操作 | 原路径 | 新路径/处理 | 原因 |
|---|---|---|---|
```

## 3. 执行

- **更新导航、README、索引**：用户同意整理后可以直接做。改之前先读原文件，只改需要改的条目。
- **移动、重命名、合并**：按授权清单逐项执行。执行前再核对一次路径，执行后检查链接，并修正受影响的导航。
- **删除**：只删除用户逐项点名的文件。宿主支持时优先移到回收站或备份目录，不直接永久删除。
- **合并重复文件**：先比对内容，保留信息最全的一份；另一份按用户意见处理。
- 某一步失败时停下，报告已完成和未完成的项目，不跳过失败继续执行。

## 4. 收尾

- 列出实际改动：新建、修改、移动、删除的文件。
- 再检查一遍导航链接。
- 用户启用了对话存档时，可以把这次整理存成一张进度卡片。
