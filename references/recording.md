# 记录规范

## 三类记录

知识：记录用户的理解、已确认的解释及必要边界。不要把 AI 的整段回复默认当成用户学会的内容。

想法：写清用户想解决的问题、提出的办法、适用对象和待验证事项。用户原意与 AI 补充分别标识。

进度：保留当前目标、重要约束、已完成与已确认的内容、未完成或待核验的事项、关键文件位置、下一步。多个任务分别存档，不把一个项目的状态套用到另一个项目。

每张卡片优先控制在几段短文内，以找回和继续工作所需信息为准。可有较短的原话，完整证据仍留在原文件或原对话。记录来源不要求读取聊天数据库；无法取得对话链接时写“当前对话”，加任务主题或必要短引文。

## 脚本输入

先通过文件工具把 JSON 写入宿主的任务临时目录，再调用 `save`。不要把对话文本拼进 shell 命令。下面是虚构示例，不是真实用户存档。

```json
{
  "kind": "idea",
  "title": "给新手保存聊天中的收获",
  "summary": "在明确的收获和阶段节点保存简短卡片，以便检索与接续。",
  "origin": "user",
  "status": "proposed",
  "userQuote": "我想把今天的学习收获留下来",
  "keywords": ["新手", "对话资产", "接续"],
  "sources": ["当前对话：用户提出自己的产品需求"],
  "body": "用户需求：保存有价值的知识、创意和进度。\n\n待验证：怎样减少漏记，同时避免把所有聊天都存下来。"
}
```

- `kind`：`knowledge`、`idea`、`checkpoint`。
- `origin`：`user`、`assistant`、`joint`、`source`。归属是内容的来源；整理文字可由 AI 完成。用户归属必须提供可核对的 `userQuote`；其他归属可不填引文。
- `status`：`confirmed`（用户明确确认的理解或事实）、`proposed`（设想或建议）、`unverified`（待核验）。用户确认的设想仍为 `proposed`，不因此声称产品效果成立。
- `keywords`：最多 12 个短词；搜索时若没有命中，换同义词或按任务拆开查询。
- `sources`：路径、网址或明确的对话出处。不得编造页码、时间戳或来源。
- `body`：卡片正文；checkpoint 应明确列出目标、约束、完成、待办、来源路径、下一步。没有依据的字段写“尚未确认”，不能补造。

脚本返回记录 ID、实际路径和是否重复。重复提交同一条记录复用文件；新增见解另存，并在正文里引用旧记录。脚本不会推断内容是否正确，Agent 负责归属与确认状态。

## 文件与检索

自动模式在知识库根目录下创建 `对话资产/目录.md`，其下 `知识/`、`想法/`、`进度/` 保存 Markdown。每张卡片首行含管理元数据，请保留；正文可以阅读和增补。脚本不会覆盖已有卡片。元数据错误会阻止写入并给出路径，避免静默漏记。

目录只显示各类最近 10 条，旧记录继续保留。`search` 检索全部受管记录的标题、简述和关键词；命中后 `read` 才展开正文。内容只在正文时可进一步在该资产目录内全文搜索，仍先返回相关片段。

`resume` 只返回一条候选进度记录。带任务关键词时按标题、简述和关键词匹配；没有命中返回空，不改用其他任务。Agent 仍须核对用户当前意图。

目录是脚本生成的索引；无需手工修改。分类文件夹里的系统文件（如 `.DS_Store`、`Thumbs.db`）会被忽略；其他非卡片文件会被跳过，并在返回结果的 `skipped` 中列出，Agent 应告知用户，不自动删除。并发写入遇到锁会停止，稍后重试；疑似遗留锁先确认没有进行中的写入，不自动删锁。`check` 可重建受管目录并检查元数据和链接；它不判断事实真伪。旧版 chat-knowledge 生成的目录和卡片可以继续读取。

无 Node 的手工模式：记录存入 `对话资产-手工/` 的带日期 Markdown，在该目录 `目录.md` 维护标题、简述和路径。不要把手工文件混入脚本管理目录。只声称手工写入与读回已验证。
